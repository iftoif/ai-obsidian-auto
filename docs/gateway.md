# 消息网关（Hermes Gateway）—— 本系统最大价值所在

> 如果你的时间只够装一个组件，**先装网关**。它是这套系统里离你最近的入口：手机随时指挥 AI，聊天自动沉淀，定时推送。

## 1. 网关是什么

网关是一个 **7×24 运行的「消息平台 → AI」接入层**，跑在你的 Linux 服务器上：

```text
你的手机（微信 / Telegram）
        │ 发消息
        ▼
┌─────────────────────────────┐
│  Hermes Gateway（服务器）    │
│  • 微信 Bot（iLink 协议）    │
│  • Telegram Bot（官方 API） │
│  • 7×24 在线，断了自动重连   │
└─────────────┬───────────────┘
              │ 调用 LLM 回答你
              │ 会话自动写入 Vault
              │ 图片落盘 + vision 分析
              ▼
      Obsidian 知识库（自动沉淀）
```

一句话：**把微信/Telegram 变成你的 AI 对话入口，聊完自动进知识库。**

## 2. 为什么网关是最大价值（先装它）

| 价值 | 说明 | 没有网关就享受不到 |
|---|---|---|
| 📱 **手机随时指挥 AI** | 出门在外、躺在沙发上，微信发一条消息就能让 AI 干活（查资料、写东西、提醒你） | ❌ 只能在电脑前用 CLI |
| 💬 **聊天自动沉淀** | 你在微信/Telegram 里和 AI 的对话，和其他客户端一样自动进 Raw → 蒸馏 → Wiki | ❌ 手机聊天白白流失 |
| ⏰ **定时主动推送** | 晨间/晚间财经简报、提醒事项，AI 主动发给你 | ❌ 只能你去找 AI |
| 🔔 **系统事件通知** | 新机器加入、蒸馏失败、备份完成——服务器主动通知你 | ❌ 出了问题你不知道 |
| 🖼️ **多模态入口** | 发图片给 AI：自动落盘、vision 识别、内容进知识库 | ❌ CLI 发图麻烦 |
| 🔒 **数据归己** | 对话存在你自己的服务器上，不依赖第三方云 | ❌ 用网页版 AI = 数据在别人家 |

**核心体验**：装完网关后，你在手机上和 AI 的每一次对话、每一张图片，都会在 4 小时内变成知识库里的结构化页面。这才是「第二大脑」最自然的输入方式——比坐在电脑前敲 CLI 顺滑得多。

## 3. 网关能做什么（功能清单）

### 3.1 对话

- 在微信/Telegram 里直接和 AI 聊天（使用你配置的 LLM）
- 多轮上下文、连续对话
- 支持发送图片（vision 分析）、文件

### 3.2 定时任务推送

```text
晨间 06:00 → 财经与 AI 简报（全球市场 + AI 行业动态）
晚间 22:00 → 当日复盘简报
自定义   → 任意提醒（比如「每月 1 号提醒我交房租」）
```

### 3.3 系统通知

```text
🖥️ 新机器加入生态：<WORKSTATION_HOSTNAME>（工作站）
❌ 蒸馏失败：主 provider 额度耗尽，已降级 deepseek
✅ 备份完成：vault 已加密备份到网盘
```

### 3.4 图片管线

```text
微信收到图片 → 落盘 assets/weixin/ → vision 识别 → 内容进知识库 → Obsidian 可见
```

## 4. 微信 vs Telegram：优缺点与选型

### 微信（iLink Bot）

**优点**：

- ✅ **零学习成本**：你天天用微信，不用装新 App，爸妈也能参与
- ✅ **国内网络直连**：不需要代理
- ✅ **图片/文件方便**：手机截图直接发
- ✅ **多账号支持**：主号、小号各跑一个 gateway（互不干扰）

**缺点**：

- ❌ **非官方接口**：基于 iLink Bot 协议（第三方实现），微信官方没开放 Bot API——存在账号风控风险，建议用小号
- ❌ **频率限制**：发送过快会被限流（实践中用 2 秒间隔 + 断路器规避）
- ❌ **图片有清理风险**：需要配置图片永久落盘（本系统已内置处理）
- ❌ **扫码登录**：每个账号需要扫码，token 过期要重新扫

### Telegram（官方 Bot API）

**优点**：

- ✅ **官方 Bot API**：稳定、规范、无风控风险，BotFather 创建即可
- ✅ **多端同步**：手机/平板/电脑消息无缝
- ✅ **通知可靠**：系统级推送，适合接系统事件通知
- ✅ **富文本/按钮/文件**：Bot 生态完善

**缺点**：

- ❌ **国内网络问题**：需要代理才能连上 Telegram 服务器
- ❌ **要装 App**：国内用户手机上通常没有 Telegram
- ❌ **BOT token 管理**：token 即账号控制权，要保管好

### 选型建议

| 你的情况 | 建议 |
|---|---|
| 国内用户，图省事 | **微信为主**（小号） + Telegram 接系统通知 |
| 在意稳定性、有代理 | **Telegram 为主** |
| 两个都要 | 双跑：微信日常对话，Telegram 接通知和简报 |

> 实践参考：本系统的作者跑 **微信 ×3（main/小号/另一个小号）+ Telegram**，微信负责日常对话和财经简报推送，Telegram 负责系统通知。

## 5. 部署

### 5.0 安装 Hermes Agent（前置）

> Hermes 既是消息网关，也是蒸馏的运行时依赖。装好后 `hermes` 命令必须在 PATH 中。

```bash
# 方式一：官方安装（推荐）
# 见 Hermes 官方仓库 https://github.com/NousResearch/hermes-agent 的安装说明
# 安装完成后验证：
which hermes && hermes --version

# 方式二：若你的 fork/分发渠道提供了一键安装脚本，按它的说明执行
```

> 安装完成后，继续下面的网关配置；即使不用网关，蒸馏功能也需要 Hermes（见 quickstart.md 第 4.5 步）。

### 5.1 微信网关

```bash
# 为每个微信账号创建一个 profile
hermes gateway add wechat --profile wechat2

# 启动后扫码登录（iLink 协议）
systemctl --user start hermes-gateway-wechat2
# 首次启动会生成二维码，扫码登录
```

### 5.2 Telegram 网关

```bash
# 1. 在 Telegram 里找 @BotFather，发送 /newbot 创建 Bot，拿到 token
# 2. 配置
# .env 或 ~/.hermes/.env 里加：
TELEGRAM_BOT_TOKEN=123456:ABC-DEF...   # 你的 bot token
TELEGRAM_CHAT_ID=你的chat_id            # 你的私聊 id（@userinfobot 可查）

# 3. 启动
systemctl --user start hermes-gateway
```

> 国内网络连 Telegram 需要代理；部署细节见 [deployment.md](deployment.md) 的网关章节。

## 6. 踩坑记录（真实经验）

1. **微信限流**：腾讯 iLink Bot API 有频率限制，发送过快会报错（ret=-2）。规避：消息间隔 ≥2 秒 + 失败断路器（60 秒冷却）。
2. **Telegram 迁移到服务器的三个坑**：DNS 污染（本地 DNS 把 Telegram 域名解析到错误 IP）、代理误拉入（gateway 的 HTTPS_PROXY 把 Telegram 流量带进代理导致挂起）、fallback transport 自冲突（高延迟环境下连接池冲突）。逐一排除后才能稳定连接。
3. **微信图片会丢**：默认微信收到的图片存在临时目录，24 小时后被清理。必须配置「图片永久落盘 + 导出引用」，否则蒸馏时图已经没了。
4. **启动通知别开**：网关上下线通知会触发消息风暴（重启一次发一次），还会加剧微信限流。默认关闭。
